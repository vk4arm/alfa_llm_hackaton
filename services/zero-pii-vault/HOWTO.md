# Краткая инструкция по настройке Zero-PII Vault (HOWTO)

## 1. Запуск сервиса
Запуск микросервиса и сопутствующего Redis-хранилища сессий выполняется одной командой:
```bash
docker-compose up -d
```

## 2. Распределение CPU и воркеров
В соответствии с аппаратными квотами (суммарно 4 vCPU):
* **Zero-PII Vault:** выделяется **3 CPU-ядра** (`cpus: 3.0`) и **3 параллельных воркера** через переменную окружения `VAULT_WORKERS=3`.
* **Redis:** резервируется **1 CPU-ядро** (`cpus: 1.0`).

Параметры задаются в `docker-compose.yml` в секциях `environment` и `cpus`.

## 3. Настройка сетевого файервола (Firewall)
Правила фильтрации входящего трафика настраиваются в файле `config/firewall.json`. Доступ разрешается по CIDR-нотации:
```json
[
  {
    "name": "global_access",
    "subnet": "all"
  },
  {
    "name": "internal_banking_core",
    "subnet": "10.0.0.0/8"
  },
  {
    "name": "local_dev",
    "subnet": "127.0.0.1/32"
  }
]
```
* `"subnet": "all"` (или `"0.0.0.0/0"`) — разрешает доступ со всех IP-адресов.
* `"subnet": "10.0.0.0/8"` — доступ только из указанной внутренней подсети.
* Если файл отсутствует или пуст — по умолчанию доступ запрещён (Deny All).

## 4. Конфигурация правил детекции и списков сущностей
* `config/rules.yaml` — перечень регулярных выражений, правила контекстного окна (`context_window_chars: 80`) и флаги включения/выключения конкретных типов ПДн (`enabled_masks`).
* `config/famous_persons.yaml` — белый список публичных и исторических персоналий (не подлежащих маскированию вне финансового контекста).

## 5. Проверка работоспособности
Проверка доступности и статуса сервиса:
```bash
curl -i http://localhost:8000/health
```
Ожидаемый ответ: `HTTP 200 OK` с `{"status":"ok"}`.
